0. 30 秒总览
------------------------------------------------------------
进程看到的是虚拟地址，RAM 用的是物理地址。
MMU 用页表把「虚拟页号」换成「物理页号」，页内偏移不动。
页表自己也占物理页。能给程序数据用的帧 = 总帧 - 内核 - 页表页 - 已占用数据页。


1. 专有名词与缩写
------------------------------------------------------------
VA          Virtual Address          虚拟地址（进程指针里的数）
PA          Physical Address         物理地址（真正发给 RAM 的数）
VPN         Virtual Page Number      虚拟页号（VA 的高位）
PPN / PFN   Physical Page Number /   物理页号（帧号）
            Page Frame Number
offset      page offset              页内偏移（VA/PA 的低位，选页里第几个字节）
page        页                       虚拟地址空间里的一块固定大小区域
frame       帧                       物理内存里同样大小的一块
PTE         Page-Table Entry         页表项：一格目录，通常 8 字节
PT          Page Table               页表：PTE 组成的数组
page-table page / 页表页             专门存放 PTE 的那一物理页
data page   / 数据页                 存放代码/数据/堆/栈的那一物理页
MMU         Memory Management Unit   硬件，负责 VA→PA
TLB         Translation Lookaside    最近 VPN→PPN 的硬件缓存
            Buffer
ASID        Address-Space ID         给 TLB 项打的进程标签
satp        Supervisor Addr. Trans.  RISC-V：根页表物理地址所在寄存器
            and Protection
hit / miss  TLB hit / TLB miss       翻译在不在 TLB 里
page fault  缺页                     PTE 说这页现在不能用（不在 RAM / 无权限）
EAT         Effective Access Time    平均访存时间
Sv39        RISC-V 39-bit VA         课上常用：39 位虚拟地址 + 4 KiB 页
KiB / MiB / GiB                      2^10 / 2^20 / 2^30 字节


2. 基础量（课上默认，先写在卷子角落）
------------------------------------------------------------
常用页大小          4 KiB = 4096 = 0x1000 = 2^12 字节
                    → offset 一定是 12 位
                    → 十六进制里最低 3 位就是 offset

课上也出现过        512 B 页 → offset 9 位（370 期中那套题）

PTE 大小            8 字节（64 位）
一张页表页能装      4096 / 8 = 512 = 2^9 项
                    → 一层索引宽度 = 9 位

Sv39                VA 39 位，offset 12 位，VPN 27 位
                    单层表：2^27 * 8 B = 1 GiB   （所以必须多层）

30 位 VA + 4 KiB    offset 12，VPN 18
                    9 + 9 + 12 → 正好两层


3. 地址怎么拆
------------------------------------------------------------
VA = [ VPN | offset ]
PA = [ PPN | offset ]          // offset 原样拷贝

4 KiB 页：
  VA 0x3A7C = VPN 0x3 | offset 0xA7C
  页表 0x3 → 0x9
  PA = 0x9A7C

看十六进制：页大小 0x1000 时，最低 3 个 hex 位是 offset。
看二进制：低 12 位是 offset，左边全是 VPN。

多层时 VPN 再切成各层索引，offset 仍然不动：

  30-bit VA / 4 KiB / 8B PTE（两层）：
    [ 9-bit L1 | 9-bit L0 | 12-bit offset ]

  30-bit VA / 512 B / 8B PTE（370 Q23/Q24，根只有 3 位）：
    [ 3 | 6 | 6 | 6 | 9-bit offset ]     共 4 层
    一张表：512 B / 8 B = 64 = 2^6 项，所以中间层 6 位


4. 一次翻译在干什么
------------------------------------------------------------
1. 程序发出 VA
2. TLB 先看有没有 VPN→PPN
     有  → TLB hit  → 直接拼 offset，访问数据页
     没有→ TLB miss → 走页表（page-table walk）
3. walk：用 VPN 各段当索引，从根表往下读 PTE
4. 最后一层 PTE 给出 PPN + 权限位
5. PA = PPN || offset，去数据页读/写那个字节
6. 把 VPN→PPN 填进 TLB

PTE 有效且页在 RAM  → 翻译成功
PTE 说不在 RAM / 没映射 / 权限不对 → page fault，进内核


5. 数据页 vs 页表页（必考分界）
------------------------------------------------------------
数据页
  装程序真正用的内容：代码、全局数据、堆、栈、文件映射
  由「最底层 PTE」的 PPN 指向
  用户最终读写的是它

页表页
  整页都是 PTE，是目录，不是程序数据
  由「上一层 PTE」的 PPN 指向（根表地址在 satp）
  MMU 翻译时读的是它

两者都是同样大小的物理帧，只是内容不同。
数据页的 4096 字节不会被 PTE 挖走一块。
PTE 单独住在页表页里。

总占用帧：
  总页数 = 数据页数 + 页表页数
  （再加上内核等，如果题目把内核单独算）


6. 为什么虚拟页和物理页 offset 一样
------------------------------------------------------------
页和帧被规定成一样大。
一页里的第 k 个字节，搬到哪一帧，仍是那一帧的第 k 个字节。
硬件因此可以「只换页号，低位原样拷贝」。

变的是住在哪一栋楼（页号），不变的是房间号（offset）。


7. PTE 算在 VPN 里还是 offset 里
------------------------------------------------------------
都不算。PTE 不是 VA 里的一段字段。

VA 只有两段：VPN + offset
  VPN     = 钥匙，用来当页表下标，把 PTE 找出来
  PTE     = 抽屉里的纸条，写着 PPN 和权限
  offset  = 找到那一页之后，取第几个字节

多层时：L2/L1/L0 索引全部来自原来的 VPN，不是 offset。

两个「页内偏移」不要混：
  (a) VA 自带的 offset
        → 只用在最后的数据页
  (b) 读页表时的页内偏移
        → 这一层索引 × PTE大小（例如索引 5 × 8 = 40）
        → 用来在页表页里定位那一条 PTE
        → 不是 VA 末尾那个 offset


8. 「要除掉」——三种完全不同的除/减
------------------------------------------------------------
错觉：物理页 4096 字节里要扣掉若干字节给 PTE。
真相：数据页 4096 字节全给数据。下面三种才是「除掉」。

(1) 一张页表页能装几项（除法）
      项数 = 页大小 / PTE大小
      4 KiB / 8 B = 512 → 一层索引 9 位
      512 B / 8 B = 64  → 一层索引 6 位

(2) 物理内存里哪些帧不能再当数据页（减法）
      能给数据用的帧 = 总帧 - 内核帧 - 已分配页表页 - 已占用数据页
      页表占的是整帧，不是帧里的几个字节

(3) PTE 内部的位（位域，不是字节）
      64 位 PTE 里一部分是 flag：V/R/W/X/U/G/A/D …
      取出 PPN 时丢掉这些 flag
      不影响数据页仍然是 4096 字节


9. 层数怎么来的（VPN 为什么「除以」一层索引位数）
------------------------------------------------------------
不是「VPN 这个整数 ÷ PTE」。
是「VPN 有多少位，一层一次只能看其中几位」。

一层索引位数由 (1) 决定：装得下 2^k 项，就只能吃 k 位。
VPN 位数 = VA位数 - offset位数。
层数 ≈ VPN位数 / 一层索引位数
        （除不尽就再加一层，或让根表项数少一点，根索引短一点）

例子：
  30-bit VA，4 KiB，8B PTE
    VPN = 18 位，一层 9 位 → 18/9 = 2 层

  39-bit VA，4 KiB，8B PTE（Sv39）
    VPN = 27 位，一层 9 位 → 27/9 = 3 层

  30-bit VA，512 B，8B PTE（370 期中）
    offset 9 位，VPN 21 位
    中间层 6 位（64 项），根只剩 21-18=3 位 → 根 8 项，共 4 层


10. 多层为什么省空间
------------------------------------------------------------
单层：每个可能的 VPN 都要预留一个 PTE
  Sv39：1 GiB 页表，哪怕进程只用了几页数据

多层：上层某项 unmapped → 整棵子树的页表页都不分配
  Lecture 10 例子：30-bit VA，只用 1 个数据页
    单层 = 2^18 * 8 B = 2 MiB
    两层 = 1 张 L1 + 1 张 L0 = 8 KiB

省的是「没用到的那些下层表」。
地址很密、几乎每页都用时，多层省得少，walk 还更慢 → 所以要 TLB。


11. 最少 / 最多页表页（数据页挤 vs 散）
------------------------------------------------------------
口诀：
  数据页越挤（VPN 高位相同）→ 共享上层表 → 页表页少
  数据页越散（高位都不同）→ 每层都可能各长一张新表 → 页表页多
  根表通常只有 1 张
  叶子表最多可以「一页数据配一张」（受该层项数、根的扇出限制）

370 期中风格（Tutorial 4 PQ2 continued）
  30-bit VA，512 B 页，8B PTE，4 层，根只有 8 项
  映射正好 10 个数据页
  最少：10 个数据页塞进同一张 L0（64 项够用）
        1 root + 1 L2 + 1 L1 + 1 L0 + 10 数据 = 14
  最多：根扇出最多 8 张 L2；L1、L0 可以各 10 张
        1 + 8 + 10 + 10 + 10 数据 = 39
  答案：最少 14，最多 39

数「已经碰到的几个地址占了几张表」时：
  从高位往低位看，索引相同 = 共享那一层的同一张表
  索引第一次不同 = 从那一层开始分叉，多一张新表
  每张已分配的表都占满一整页/一整帧（哪怕只用了一项）


12. TLB、miss、fault（三个不要当成一个）
------------------------------------------------------------
TLB hit     翻译已缓存，不去读页表页，直接访问数据页
TLB miss    翻译没缓存，要 walk 页表；页本身可能已经在 RAM
page fault  当前 PTE 完不成这次访问（没映射 / 不在 RAM / 权限）

所以：TLB miss ≠ page fault

EAT 课上模型（两层、先查 TLB）：
  Hit  = t_TLB + M
  Miss = t_TLB + L*M + M          // L 层页表各一次，再加数据一次
  EAT  = p_hit * Hit + p_miss * Miss

例：80% hit，TLB 10 ns，一次内存 100 ns，两层
  Hit  = 110 ns
  Miss = 10 + 2*100 + 100 = 310 ns
  EAT  = 0.8*110 + 0.2*310 = 150 ns
  若没有 TLB，每次 3 次内存 = 300 ns

上下文切换：
  不同进程同一个 VPN 可以对应不同 PPN
  → 清 TLB，或给 TLB 项打 ASID


13. 缺页之后（和「能给数据用的帧」的衔接）
------------------------------------------------------------
合法但页不在 RAM：
  1. MMU 陷入内核
  2. 内核确认访问合法
  3. 有空闲帧 → 拿来用；没有 → 置换算法选牺牲页
  4. 装入或填零，改 PTE，处理 TLB
  5. 重试那条指令

空闲帧被页表占掉后，能拿来满足缺页的数据帧就更少。


14. 情景题（本轮自拟）标准答案
------------------------------------------------------------
给定：
  物理内存 4 MiB，页 4 KiB，PTE 8 B
  30-bit VA，两层 9+9+12
  内核已占 64 帧
  一个用户进程映射正好 20 个数据页

中间量：
  总帧 = 4 MiB / 4 KiB = 1024
  一张表 512 项，20 < 512，可共享一张 L0

A. 最小页表开销（20 页挤在一起）
  页表页 = 1 L1 + 1 L0 = 2
  占用   = 64 + 20 + 2 = 86
  空闲   = 1024 - 86 = 938
  还能当数据页的帧 = 938

B. 最大页表开销（两层下尽量拆）
  只有一张 L1，最多 20 张不同 L0
  页表页 = 1 + 20 = 21
  占用   = 64 + 20 + 21 = 105
  空闲   = 1024 - 105 = 919
  还能当数据页的帧 = 919

C. 为什么不是 1024 - 20
  内核帧和页表帧都不能再装用户数据。
  能给数据用的帧 = 总帧 - 内核 - 用户数据页 - 用户页表页


15. 你的易错点（本轮对话里出现过的）
------------------------------------------------------------
[错] 虚拟页和物理页 offset 不同
[对] 页=帧大小，offset 位数相同、数值原样拷贝

[错] PTE 是 VA 里的一段，要么算在 offset 里要么算在 VPN 里
[对] PTE 是查表结果；VPN 是索引；offset 是数据页内位移

[错] 数据页 4096 字节里要扣掉 PTE 占用的若干字节
[对] 数据页整页给数据；PTE 住在单独的页表页
     「除掉」只出现在：页大小/PTE大小、总帧减页表帧、PTE 里的 flag 位

[错] 64+20+2 的 2 不知道从哪来
[对] 最小情况的 1 张根表 + 1 张叶子表

[错] 页表「必须」两层
[对] 层数由「VPN 位数 / 一层索引位数」决定，换参数就换层数
     这题两层是因为 18/9=2，不是宇宙定律

[错] VPN 除以 PTE（把页号当整数去除以 8 字节）
[对] 除的是位数：VPN有多少 bit ÷ 一层索引有多少 bit = 大概几层
     另一刀才是 页大小÷PTE大小 = 一层几项

[错] TLB miss 就是缺页
[对] miss 只是翻译没缓存；fault 才是 PTE 完不成访问

[错] 算进程占了多少内存只数数据页
[对] 必须加上页表页（以及题目里单独列出的内核）


16. 考试动手顺序（建议默写）
------------------------------------------------------------
1. 写页大小 → offset 几位 → VPN 几位
2. 写 PTE 大小 → 一层几项 → 一层索引几位 → 几层
3. 把给定 VA 拆成各层索引 + offset（先写二进制再分组）
4. 问翻译：换页号、留 offset
5. 问占多少：数共享了几张表，每张整页计
6. 问最少/最多：挤在一起 vs 按扇出拆开
7. 问还能给数据用：总帧 - 所有非数据占用
8. 问时间：先判断 hit/miss/fault，再写 EAT
