三、专有名词和缩写词典
--------------------
UB              Undefined Behavior 未定义行为
VA              Virtual Address 虚拟地址
PA              Physical Address 物理地址
VPN             Virtual Page Number 虚拟页号
PFN / PPN       Physical Frame/Page Number 物理页帧号
PTE             Page Table Entry 页表项（页表里的一行）
TLB             Translation Lookaside Buffer 地址翻译缓存
EAT             Effective Access Time 有效访问时间
COW             Copy-on-Write 写时复制
PCB             Process Control Block 进程控制块
PID             Process ID 进程号
IPC             Inter-Process Communication 进程间通信

FCFS            First Come First Serve 先来先服务（非抢占）
SJF             Shortest Job First 最短作业优先（非抢占）
SRTF / SRT / STR
                Shortest Remaining Time First 最短剩余时间优先（抢占式 SJF）
RR              Round Robin 时间片轮转
CFS             Completely Fair Scheduler 完全公平调度（看 virtual runtime）
EEVDF           Earliest Eligible Virtual Deadline First
                先看谁被欠了服务，再选虚拟 deadline 最早的

First Fit       首次适应：从左/从头找第一块够大的空闲块
Best Fit        最佳适应：找浪费最少的那块
Worst Fit       最差适应：找当前最大的空闲块
Buddy Allocator 伙伴分配器：块大小必须是 2 的幂，对半切，伙伴才能合并
Split           把大空闲块切开，一部分给用户
Coalesce        相邻空闲块合并
Free block      连续的一段空闲内存（中间被占用就分成多块）
Internal frag.  内部碎片：分给你的比你要的大（Buddy 常见）
External frag.  外部碎片：空闲总量够，但被切碎用不了

Page            页：固定大小的内存块（本题 512B）
Frame           页框：物理内存里同样大小的块
Data page       数据页：真正放代码/变量的页
Page table page 页表页：专门用来存放页表的页
Page fault      缺页异常：要的页不在内存，或权限不够（如写只读页）
Demand paging   按需分页：用到才装入物理内存
Overcommit      超额承诺：malloc 成功不代表物理页已经备好

User mode       用户态
Kernel mode     内核态
Mode bit        模式位，标识当前特权级（由硬件在陷入时切换）
System call     系统调用：用户态通过陷阱进入内核
Trap / Exception 陷入/异常
Monolithic      宏内核：核心服务都在内核里，快，故障影响面大
Microkernel     微内核：尽量少的内核，服务在用户态，隔离好，开销大

fork()          创建子进程，复制地址空间（现代 OS 用 COW）
exec / execl    用新程序替换当前进程映像
wait()          父进程等待子进程结束
pipe()          管道，用于父子进程通信
read()          管道为空时会阻塞
write()         系统调用，直接写文件描述符，不走 stdio 缓冲
printf()        库函数，通常带缓冲，进程退出或遇换行才刷出
malloc()/free() 用户态堆分配/释放

Cache affinity  缓存亲和性：进程留在同一 CPU 上，缓存更热
Load balancing  负载均衡：把任务在 CPU 之间挪动
TLB shootdown   多核上通知其他 CPU 作废旧 TLB 项
TLB invalidation 作废本机或指定地址的 TLB 条目


四、核心知识点（按主题）
----------------------

4.1 C 语言 / 内存 / UB
- 局部变量在函数返回后销毁。返回它的地址本身不立刻 UB，
  之后解引用这个悬空指针才是 UB。（Q1）
- 用户程序里的 &g、&l、malloc 返回的指针，都是虚拟地址。（Q2）
- 两个独立进程：各自一份栈、各自一份数据段。
  改自己的 g 不会改到另一个进程的 g。（Q4）
- 结构体对齐：成员按自身对齐要求摆放；
  整个结构体大小必须是「最大成员对齐」的倍数。
  char+char+int+char+int+char -> 20，不是 17。
  最后一个 char 后面也要补齐，否则做成数组时下一元素会对不齐。（Q25）
- malloc 返回非 NULL：
  不保证物理页已经分配（overcommit）；
  不保证马上写每个字节都成功；
  进程退出后内存被 OS 回收，不是一直留到 free。（Q29）

4.2 进程、fork、管道、缓冲
- 程序 = 磁盘上的文件；进程 = 正在跑的程序 + 状态。
- 状态：Created -> Ready -> Running -> Blocked -> Ready -> Running -> Terminated（Q11）
- printf 走库缓冲；write 是系统调用，立刻出。
  printf("14"); sleep(1); write(1,"23",2);  -> 先 23 再 14，即 2314。（Q7）
- fork 两次、只 wait 一次：A 不可能最先出现，因为 wait 在 printf("A") 前。（Q8）
- fork + execl("./a.out")：execl 成功后后面的代码永不执行，
  两个进程都会再次执行同一个程序，进程数无限增长。（Q10）
- 两次 fork、只让父进程打印 p：父进程 p 变成 2，输出确定是 2。（Q12）
- pipe + 子进程先 read：管道空则阻塞，必须等父进程 write 后才能继续。
  顺序被锁死为 A 然后 B 然后 C。（Q13）

4.3 系统调用与内核
- 系统调用一定从用户态转到内核态。（Q5-1 对）
- 系统调用不是普通函数调用，参数在寄存器或用户空间，
  不必是指向内核内存的指针。（Q5-2 错）
- 切换 mode bit 的是 CPU 硬件（执行 syscall/ecall/int 时自动切），
  不是内核代码事后改的。（Q5-3 错，老师确认）
- 宏内核：服务都在内核，交互开销小，适合性能场景。
- 微内核：驱动/文件系统在用户态，故障不容易拖垮整个系统。

4.4 调度
进程：P1(0,3) P2(1,6) P3(2,3) P4(2 after P3,1)，单核。

FCFS（非抢占，按到达）：
  P1 0-3, P2 3-9, P3 9-12, P4 12-13
  完成：3, 9, 12, 13  -> Q14 E

SJF（非抢占，选已到达里最短）：
  P1 先跑完；t=3 时 P4 最短 -> P4；再 P3；再 P2
  完成：3, 13, 7, 4  -> Q15 C

SRTF（抢占，随时比剩余时间）：
  本题结果也是 3, 13, 7, 4  -> Q16 D
  和 SJF 不同在于：中途来了更短的可以抢走 CPU。

RR 时间片=2，并列时用 FCFS（P3 先于 P4 到）：
  完成：P1=8, P2=13, P3=11, P4=7  -> Q17 D

饥饿 / 能保证最终跑到：
  FCFS、RR 可以；SJF、SRTF 可能饿死长作业。 -> Q18 C

多核队列：
  全局一条：简单，但扫描慢、抢队列、破坏缓存。
  每 CPU 一条且少迁移：快，cache affinity 好。适合长寿命、反复用同一批数据的 worker。 -> Q19 E
  每 CPU 一条但频繁迁移：负载更均，但缓存变冷。

Linux 调度演变（课上讲过可考）：
  Global O(N)  : 一个大队列，每次全扫
  Per-CPU O(1): 每核自己排队，选下一个是常数时间
  CFS          : 选 virtual runtime 最小的（谁目前吃得最少谁上）
  EEVDF        : 先筛「该得到服务的」，再选 virtual deadline 最早的（更直接表达延迟）

4.5 虚拟内存与多级页表
虚拟地址空间可以大于物理内存（按需分页），也可以小于。
有效虚拟地址不必时刻在物理内存里（可换出）。
不同进程相同虚拟地址可以映射同一物理页（共享库、COW、共享内存）。

本题参数：
  VA = 30 位
  页大小 = 512B = 2^9  -> 偏移 9 位
  VPN = 21 位
  PTE = 8B
  一页能放 512/8 = 64 个 PTE = 2^6  -> 每级最多 6 位索引
  21 不能被 6 整除 -> 最少 4 级，多 3 位
  课上习惯从高到低：3 | 6 | 6 | 6 | 9
                    L3   L2  L1  L0  偏移

单级页表 PTE 个数 = 2^21  -> Q20 A
每级页表大小 = 512B       -> Q21 C
最少级数 = 4              -> Q22 A

页表页 vs 数据页：
  数据页 = 真正放程序内容的页
  页表页 = 放目录（PTE）的页
  某一级的一个 PTE 指向的是「下一级整张页表」，不是下一级的某一个格子
  只为真正用到的索引分配页表（按需）

Q23 三个地址 0x08418812, 0x08418A1A, 0x0842021F
  按 3|6|6|6|9：
    都是 L3=1, L2=2
    L1 有 3 和 4 -> 2 张 L1
    L0：前两个共用一张，第三个另需一张 -> 2 张 L0
  页表页 = 1+1+2+2 = 6

Q24 映射正好 10 个数据页：

  最多：L3 只有 3 位 = 8 项，所以 L2 最多 8 张
        1 L3 + 8 L2 + 10 L1 + 10 L0 + 10 数据 = 39
  -> Q24 D

4.6 TLB
TLB 缓存的是「最近的虚拟页 -> 物理页翻译」，不是页内容本身。 -> Q27 A
命中：直接得到物理地址。
未命中：走页表（不一定缺页；页可能在内存里只是 TLB 没缓存）。
进程切换常要刷新 TLB（每个进程翻译不同）。
权限从可写改成只读、或 COW 改映射时，必须作废旧 TLB，
多核上还要 shootdown，否则硬件可能按旧的「可写」去写。

Q26：原 TLB 时间 = 0.2T，新 = 0.1T，miss rate +10 个百分点。
单级页表下 miss 多一次内存访问。
EAT_old = 0.2T + mT + T
EAT_new = 0.1T + (m+0.1)T + T
两者相等，EAT 不变。 -> Q26 E

Q30 四句都对：
  (1) TLB miss 可以由硬件走页表，不必缺页
  (2) 普通 load/store 通常不进内核
  (3) 换哪一页由 OS 决定
  (4) 单级改多级不必然改变 TLB miss 频率（TLB 缓存的是最终翻译）

4.7 堆分配：First-Fit 和 Buddy

First-Fit（Q9）：
  从低地址找第一块够大的；太大就切开，低地址给用户；
  free 时和相邻空闲合并；向 OS 一次拿 2KiB；堆只增不减。

  补全序列：
    A=malloc(1000); B=malloc(1800); free(A); C=malloc(500); free(B);

  过程：
    malloc(1000): [A1000][free1048]                     堆2KiB  空闲1
    malloc(1800): [A1000][free1048][B1800][free248]     堆4KiB  空闲2
    free(A):      [free2048][B1800][free248]            堆4KiB  空闲2
    malloc(500):  [C500][free1548][B1800][free248]      堆4KiB  空闲2
    free(B):      [C500][free3596]                      堆4KiB  空闲1
  答案 A。

  空闲块个数 = 连续空闲被隔成了几段，不是空闲总字节。

Buddy（Q28）：
  初始 256B，请求 28,90,14,6，无 header，向上取整到 2 的幂：32,128,16,8。
    28->32: 256 对半切，分走 32，剩 128,64,32
    90->128: 分走 128，剩 64,32
    14->16: 32 切成 16+16，分走 16，剩 64,16
    6->8:  16 切成 8+8，分走 8，剩 64,8
  没有正好 16 的空闲块 -> 0 个 -> C

4.8 Copy-on-Write（图书馆那份考试的 Q7，不是 term test Q7）
fork 后：
  父、子先共享同一物理页，两边都标只读。
  谁先写 -> page fault -> 给写入方复制一页并改成可写。
  另一方再写时，若原页已只被自己映射，不必再复制，直接改成可写。
  只有「原页仍被多个映射共享」时才需要第二次复制。
  因为旧的「可写」TLB 可能还留在某些 CPU 上，内核必须在回到用户态前
  做 TLB invalidation。老师说那题选 C。


五、常考判断口诀
----------------
- 用户态地址 = 虚拟地址
- 两个进程默认不共享读写数据（除非共享内存/COW 未写）
- 系统调用 = 硬件陷入内核，不是普通 call
- printf 缓冲，write 不缓冲
- read 空管道 = 阻塞
- execl 成功 = 后面代码消失
- SJF/SRTF 不公平可能饿死；FCFS/RR 最终会轮到
- 长任务 + 热数据 = 绑核、少迁移
- 页表项 PTE = 目录里的一行
- 页表页 = 目录本身占的页；数据页 = 房间
- 多级页表开销 = 数「每一级出现了几个不同索引」
- TLB = 最近翻译的小抄，不是数据本身
- First-Fit 看第一块；Buddy 必须 2 的幂
- malloc 成功 != 物理内存已到位
